Our first story is about making GPU programming both safe and fast in Rust, and not tied to any one hardware vendor. The authors built a system that lets safe Rust code run on many types of GPUs by using the Rust compiler and LLVM tools. Normally, GPU code needs you to choose between safety and speed—Rust is known for memory safety, but this is hard to keep on GPUs. Before, developers had to use unsafe code or languages for just one kind of GPU. This new system uses Rust’s type and ownership rules to manage memory, which avoids bugs and security problems. It also uses LLVM’s tools to move data between the main computer and the GPU. One hard part is that different GPUs use different ABIs, so they made a two-step process to handle this safely. They tested the system using RAJAPerf and found their Rust code runs almost as fast as CUDA or HIP code. On Hacker News, many users are excited, saying this could help more people use GPUs safely in Rust. Some warn it’s still early and setup or debugging may be hard. Others like that it’s not tied to one hardware company, and there’s a lot of talk about memory safety and security. Some want more tools and examples, and a few wonder if Rust can ever beat hand-written GPU code. Many hope this makes Rust a top choice for high-performance computing in the future.

Next, DuckDB v2.0 is about to release, with many big new features. DuckDB can now run as a server, has a new SQL parser, adds triggers, supports a new VARIANT data type for JSON-like data, brings faster queries, adds asynchronous I/O, and a new storage format. Running as a server means DuckDB now works over the network and can connect to PostgreSQL and MySQL. The VARIANT type helps with semi-structured data like logs. Triggers let you set actions on data change, like making audit tables. The SQL language gets new features, including NEAREST joins, nested schemas, better variables, and new JSON update functions. Async I/O speeds up reading from S3 and other sources. The storage format is updated, making big tables load faster and use less memory. DuckDB’s own SQL parser helps add new features and gives better error messages. Timezone and sorting are now built-in, so there’s no need for the ICU library. Extensions use a stable C API and can work across DuckDB versions. In the comments, users are excited about DuckDB as a server and speed gains, especially for big data and recursive queries. Many like the new VARIANT type for messy data. Some warn about breaking changes and urge caution before upgrading. There’s strong interest in the new extension model, and people appreciate the open development and fast progress. Some want even more features, and some are cautious about the new storage format and backward compatibility. Overall, users thank the team for moving so quickly.

Our next story is about a new phrase: “AI;DR” (AI; Didn’t Read). The author saw this online and thinks it matters. The main point is that people now use AI to write things like emails, posts, or documents, and often send them out without checking or editing. The writer feels that if someone doesn’t care enough to read and improve their AI output, he won’t read it either. He says it’s fine for customer support, but for anything with someone’s name on it, people should add a human touch. Otherwise, the writing feels cold or odd, with clear “AI-isms.” Many commenters agree that unedited AI text sounds lazy or strange. Some say AI is good for first drafts, but humans should check the final words. Others defend AI for saving time or helping non-native speakers. Some worry AI makes online writing dull or fake, while others joke about the new phrase and see it spreading. There are calls for tools that spot AI writing, and a few think rejecting AI makes life harder for some people. In the end, most agree that caring about your words—and keeping a human touch—is important, and they like the idea of “AI;DR.”

On to security: Wiz, a security company, found a big flaw in Snowflake’s public GitHub code. The problem happened when an AI tool, GitHub Copilot Autofix, helped make a code change that let anyone run commands on Snowflake’s systems by opening a GitHub issue with a tricky title. The new code put the issue title straight into a shell command without escaping special characters, making command injection possible. Wiz’s AI tool, Red Agent, found the bug within five days. They showed they could steal Snowflake’s Jira credentials, but reported the bug right away. Snowflake fixed it quickly and checked that only Wiz had accessed the data. The main lesson is that AI code tools can make serious security mistakes, even when trying to help. These tools may not know why code is written a certain way and might remove key protections. Many on Hacker News say all AI-generated code needs real human review. Some think this is not just an AI problem but a general software problem—humans make mistakes too. Others see a growing “cat and mouse” game between AI tools that write code and AI tools that find bugs. There is praise for the fast fix, and some deep discussion about the risks of mixing AI and security.

Now, a wild theory about consciousness from Julian Jaynes. Jaynes says real human consciousness—where we talk to ourselves in our minds—only started about 3,000 years ago, after language and cities existed. Before that, Jaynes thinks people had a “bicameral mind,” where the brain’s two halves worked more separately. He believes people heard voices (which they thought were gods) giving commands. Jaynes points to old books like the Iliad or the Book of Amos as evidence, and compares them to later writings that show more self-awareness. He even suggests that mental illnesses like schizophrenia might be leftovers of this old way of thinking. The article’s author finds the theory strange but interesting and recommends reading the book before judging. There’s also a story about “alien hand syndrome,” where a man’s left hand acted on its own. In the comments, some people find Jaynes’ ideas fun to think about, even if they don’t fully agree. Others say animals seem to have consciousness, so the theory is hard to believe. Some note that gods’ voices in stories may just be a way to explain strong feelings. There’s discussion about language, self-talk, and new brain research. Many agree that Jaynes’ ideas make us look at our minds in new ways, even if he’s wrong.

Next up, Sun Clock is a special 24-hour clock that shows where the sun and moon are in the sky for your location. It gives times for sunrise, sunset, golden hour, twilight, moon phases, and more. In the Northern Hemisphere, the sun moves clockwise and the clock matches that; in the Southern Hemisphere, it can turn anti-clockwise. You can set the clock to match your sky, and it works offline as a Progressive Web App. Sun Clock is free, has no ads, and stores settings only in your browser. The code is open-source under MIT license. In the comments, people love the simple, clean design and find it useful for photography and outdoor planning. They like the privacy and offline features. Some learned new things about the sun’s path, and there are requests for alarms or a mobile app. Others discuss connecting it to smart home devices and how it helps understand time zones. Many thank the developer and enjoy playing with the tool.

In AI news, OpenAI just released GPT-5.6 with new models: Sol, Terra, and Luna. Sol stands out for much better “vision” skills—detecting objects, counting, reading text from images, and pulling out data. Sol’s object detection is a big step up, scoring 46.2 mAP@50 compared to 13.8 for GPT-5.5. It’s good at finding parts of documents and works well with crowded images, but sometimes puts boxes in the wrong place with very large images. OpenAI says cropping or resizing helps. For counting, Sol and the other new models did better than before, but some hard cases are still tricky. Sol is as good as GPT-5.5 for full OCR but a bit worse at picking out just the needed information. It handles handwritten notes and tough scenes, but misses some hard-to-read text. Sol uses more tokens, so it’s slower and more costly: about 10 seconds and 2.5 cents per image. Luna is faster and cheaper, but Sol gives the best results. Competing models like Gemini 3.5 Flash are even cheaper and sometimes win in big jobs. On Hacker News, many are impressed by Sol’s progress, but worry about the high cost and slow speed. Some say it’s finally good enough for agents or tools that need to “see” a computer screen. Others say it’s not perfect yet, especially for OCR. Overall, people agree it’s real progress, but not the best for every project.

And finally, scientists at UC Berkeley say they have discovered a new color called "olo" that only five people have seen. Olo is not a normal color—it’s outside the range of colors our eyes can usually detect. Using special lasers, researchers targeted only the M cone cells in the eye, making a color experience impossible under normal light. The closest normal shade is a bright blue-green, #00FFCC. The team named it “olo” based on its LMS color code. The five test subjects say it looks “more saturated than any color you can see in the real world.” The main scientist hopes this work might help people with color blindness or let us see more colors in the future. But not everyone is sure olo is truly a new color—some think it’s just a brain trick from the experiment. There’s a lot of excitement, but also healthy doubt. Artists want to make olo-inspired paints, even though the color can’t be shown on screens. In the comments, people are curious about how it works and if normal people might see olo one day. There’s debate about whether the experience is personal or could be shared, and some wonder about the ethics of changing how we see colors. The discussion is lively, with both wonder and skepticism.
