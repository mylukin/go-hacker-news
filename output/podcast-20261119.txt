今天先从 Anthropic 的两条消息说起。一条关乎它在股市上值多少钱，另一条关乎 Claude 做了什么样的数学。接着，我们来听一场该不该放慢 AI 研发的辩论，再聊胰腺癌早期试验、iCloud 加密、Java 的一个缺陷，以及几个把控制权交还给用户的项目。

先看上市。标题称，Anthropic 在纳斯达克首日交易中，市值达到两万亿美元。这里最容易读错的是「市值」：它是按股价算出来的全部股份的总价值，不是 Anthropic 上市筹到了两万亿美元。手头没有路透社原文，也没有 Hacker News 的讨论，所以我们先把这两个数字的概念分清，不从一条标题推断募资额或读者反应。

Anthropic 的另一条消息是，公司称 Claude 解出了两道关于黑洞的未解题。两道题都属于同一个大方向：理解在极小的尺度上，引力是怎么运作的。

第一道题的宇宙模型像一只能留住热量的碗。温度低时，里面是气体；热到一定程度，黑洞就占了上风。1983 年，Stephen Hawking 和 Don Page 算出，这不是慢慢变过去的，而是像水烧开一样，到了一个点就突然变了。问题是，他们的算法只适用于时空形状很清楚的情况。如果连时空的形状都变得模糊，这个转变还会这么突然吗？

Claude 换了一种方式描述同一个宇宙：不用引力，改用微小粒子的规则。物理学家在 2003 年就搭好了这套数学框架，但里面有几千项，一直没人算完。多个 Claude 实例分头计算，再互相检查，得出的答案仍是突然转变。一位和 Claude 合作的物理学家也走了另一条路，得到了同样的答案。这比让同一个工具把原来的计算再跑一遍，更有说服力。

第二道题的模型里，空间只有两维。物理学家可以用一个质量上限来筛理论：如果某个理论说，最轻的黑洞都比这个上限还重，就可以把这个理论排除。以前的计算机结果给出了一个不错的猜测，却没能证明。Claude 从数字里看出规律，借用另一个数学领域的工具，找到了确切的界限。它还证明，如果用不考虑黑洞自转的最简单版本，就没法把界限压得更低。第二项结果由 Lean 检查过，不过，两道题都没有直接告诉我们，现实宇宙里的引力究竟怎么运作。

这条没有附上 Hacker News 评论，但有几个问题值得聊。更难得的是 Claude 算完了一大笔账，还是它找到了新的解题方法？第二道题有一部分沿用了早先一个 OpenAI 模型提出的思路。是因此没那么意外，还是说，把别处的办法搬到新问题上，本来就是有意思的地方？人的工作也不能略过：有研究人员负责安排多个 AI 实例，也有物理学家检查第二篇论文的主要结果。这些 AI 有大约六周时间，面对的是一张列着 22 道题的清单。另外 20 道做得怎么样，或许更能帮助我们判断，这种做法能不能推广到别的研究团队。

说到 AI 的进展，Y Combinator 的第一场辩论问了一个更直接的问题：政府该不该放慢最强 AI 系统的研发？前 AI 研究员 Jacob Coxon 主张放慢，经济学家 Robin Hanson 则反对。视频页面只有章节标题，没有逐字稿，所以我们能看到双方的论点，但看不到每一步论证。

Coxon 认为，AI 到 2028 年就可能比人更聪明。现在的系统已经会做一些我们不理解的事，而他认为，一个数字可以衡量 AI 在多种任务上的整体能力。他还指出，如果最严重的后果是人类无法生存，事后再让公司赔钱就没有用了。

Hanson 则提醒，越是宽泛的说法，越容易漏掉重要细节。即便一项新工具很强，从发明走到日常工作，也可能要几十年。他更赞成让公司为造成的损害负责，而不是事先限制研发；他还担心，本来只针对最大 AI 项目的规定，最后会管到更广泛的计算机用途。辩论也谈到，新药审批的办法为什么不一定适合 AI，AI 多快能接手大量脑力工作，以及一些工作因为可供学习的例子太少，可能更难交出去。还有一个提议是，让不同的 AI 系统互相检查。

没有 Hacker News 评论，不过视频页面列了现场提问。两位到底会制定什么规则？如果中国继续研发，放慢计划怎么执行？AI 实验室需不需要像航空业那样的安全监管机构？军方已经在用 AI，这又该怎么算？公司会不会只学会通过安全检查，系统却没有更安全？有多少人失业，经济才会撑不住？暂停研发又会让我们失去什么？最后，两位都被问到，什么会让自己改主意。现场还投了票，但页面没有公布结果。

接下来是一项胰腺癌早期试验。美国医生把一种治疗用病毒注入三名患者的肿瘤。团队报告时，三人都还活着，肿瘤没有长大，但也没有缩小。这项小试验主要看安全性，不能据此判断治疗有效。

胰腺癌经常在扩散后才被发现，那时可能已经无法手术切除。肿瘤外还有一层屏障，有些药很难进去。团队使用的是一种为攻击癌细胞、尽量不伤正常细胞而设计的病毒。三位患者接受注射时，癌症都还没有扩散到胰腺以外。第一位患者是在团队公布结果的大约一年前接受注射的。三人用的都是团队希望测试剂量的十分之一。下一步，研究人员计划在另外 15 人身上测试更高剂量，也想看看与帮助免疫系统对抗癌症的药一起用会怎样。美国此前已经批准过另一种病毒疗法，用来治疗一种皮肤癌。

没有 Hacker News 评论，但文章给出了两种看法。研究负责人 Masato Yamamoto 没想到这么低的剂量就能看到肿瘤停止生长。他认为，再过一段时间，肿瘤也许会缩小。他还希望，癌细胞死亡后，免疫系统能学会认出癌细胞。这对癌症已经扩散的人可能有意义，但本次试验没有证明这一点。胰腺外科医生 Kai Brown 更谨慎：很多疗法在小试验里看着不错，到了大试验就不行了。这次没有未接受病毒治疗的对照组，所以更大的试验需要回答一个基本问题：不打这一针，肿瘤会不会也不长？

再来看英国的 iCloud 案。英国一家法院裁定，政府必须承认，它曾向 Apple 发出一份有关加密 iCloud 数据的秘密命令。法院要求公开的是命令的存在，并没有裁定命令是否合法，也没有说明政府具体要求 Apple 做什么。

按英国 2016 年的一部法律，政府可以要求科技公司修改服务来协助调查，也可以禁止公司透露自己收到了命令。2025 年，《华盛顿邮报》报道，第一份命令要求 Apple 让英国政府能够访问全球用户受保护的 iCloud 数据。英方后来撤回了那份命令，据报道又发了一份只涉及英国用户的新命令。Apple 再次到法院提出异议，并表示不会给自家服务开后门。

与此同时，Apple 不再让更多英国用户开启 Advanced Data Protection，也就是高级数据保护。之前已经开启的人可以继续用。开启后，连 Apple 都无法读取更多类别的 iCloud 数据，包括备份。不开启，iCloud 也有加密，只是 Apple 仍能读取其中一部分数据，并可能依法交出。这样一来，两个人哪怕用同样的手机、买同样的 iCloud 套餐，受到的保护也可能不同。

政府说，这些权力有助于合法调查、保护公众，还说公开哪些公司收到了命令，可能帮到想危害国家的人。法院认为，政府没有证明仅仅承认这份命令的存在就会危及国家安全。权利团体则说，如果政府连发没发命令都不承认，外界就很难监督这项权力。预计 2027 年会有一次更全面的听证。这条也没有附上 Hacker News 评论。对开发者来说，值得想的是：如果下一个收到命令的是另一家云服务商，客户怎么知道谁能读取自己的数据？政府又能公开多少信息，而不泄露调查细节？

下面是 Java 的一条缺陷报告。2026 年 9 月 9 日，一位 OpenJDK 开发者报告说，Java 的快速 Base64 解码器有个问题，并提交了修复建议。Base64 能把数据表示成文本，解码器负责把文本还原成数据。在支持 AVX-512 的部分机器上，Java 可以一次处理多个字节，加快这个过程。

问题出在处理末尾几个字节的代码上。报告说，遇到无效的结尾时，解码器可能算错输出大小，把数据写到预留空间之外，破坏内存里的其他数据。GitHub 页面链接了几起 Java 崩溃报告，但这些链接不能证明崩溃就是这个缺陷造成的。建议的修法是，把短尾交回普通 Java 代码处理。标题用了「java4shell」这个名字，不过报告没有证明有人能借此运行自己的代码，也没列出哪些 Java 版本已经修复。

没有 Hacker News 评论，但 GitHub 上有一段值得留意的记录。OpenJDK 的机器人先提示，这个改动还不能合并：它查不到链接指向的缺陷报告，而这项改动需要两次代码审查，页面上一次也没有。到了 11 月，另一个机器人提醒，这个请求已经八周没动静了，那条提醒收到了好几个踩。作者当天关闭了请求，没有合并。后来有人问为什么关掉，这个问题得到了 34 个赞，但线程里没有公开答复。这个请求没合并，不等于我们已经知道其他版本有没有修。

从代码审查转到设计交接。Onlook 团队在 Hacker News 上介绍了一款开源桌面工具，想给 Figma 和 Webflow 的用户多一个选择。它的想法是，与其先画一张图，再请开发者照着重做，不如直接在能跑的网站或应用里改。

Onlook 会打开一个 Git 项目，在你的电脑上运行它。手机、平板、桌面的画面可以并排看。想让按钮显眼一点？点中按钮，把要求告诉 AI 就行。Onlook 本身不带 AI，要接上 Claude Code 或 ChatGPT Codex。AI 改的是项目文件，应用重新加载后就能看到效果。改动在一份独立的 Git 副本里进行，不会碰你的主项目目录。你也可以在项目之外快速画草图，分享成网页、图片或 PDF。改动准备好了，再发一个 pull request 让团队审查。

桌面版目前有 Mac 下载，没有 Windows 或 Linux 下载。从源码自己构建，不需要 Onlook 账号。Mac 下载版会收集使用数据，但可以在设置里关掉。手头没有这次发布的 Hacker News 评论，先不替读者评价。

接下来是「Garage Door Spam」。车库门通知，本来应该告诉你门开了。结果 2026 年 10 月，有位作者收到的却是一条广告。Chamberlain 的 myQ 应用里本来就有广告，但作者一直留着它，因为人在外面时，门一开，通知就能提醒自己看看是怎么回事。广告进了通知栏，这下作者决定自己接管。

Chamberlain 早在 2023 年底就切断了其他应用的接入。作者买了两块叫 ratgdo32 的小型 Wi-Fi 板，每块大约 62 美元，接到原来的开门器上，让它们走家里的网络。板子支持 Apple HomeKit，可以请 Siri 打开任意一扇门。这个项目还让作者想起父亲以前的办法：在走廊装一盏灯，车库门开着，灯就亮。现在，一个小程序在夜里每十分钟检查一次，发现门还开着，就发 Slack 消息。

作者还给开源项目提交了一处小改动，维护者也乐意收下。人在外面时，作者可以用 Tailscale 确认两块板还在工作。现在车库门不再依赖 Chamberlain 的在线服务，新通知甚至会说是谁开的门。这条没有附上 Hacker News 评论，不过作者为什么换掉原来的系统很清楚：一条本该提醒你留意家里的通知，不该让你先猜它是不是广告。
