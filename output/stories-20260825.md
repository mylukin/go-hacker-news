## FDA authorizes first wearable device that monitors ketone and blood sugar levels

- 原文链接: [FDA authorizes first wearable device that monitors ketone and blood sugar levels](https://www.fda.gov/news-events/press-announcements/fda-authorizes-first-wearable-device-continuously-monitors-both-ketone-levels-and-blood-sugar)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49439017)

The FDA has approved a new wearable device called the Libre Duo 10 Day, which can track both blood sugar and ketone levels all the time for people with diabetes. This is the first device in the U.S. that lets people see their ketone and glucose levels together, helping them catch problems early.

The device is for people aged 2 and older. It is important because people with diabetes, especially type 1, need to watch their blood sugar and ketone levels. If ketone levels get too high, it can cause diabetic ketoacidosis (DKA), which is very dangerous. Before this device, people had to check ketones with a separate test, and these tests only gave one result at a time. The Libre Duo 10 Day checks both glucose and ketones every minute, all day and night, using a small sensor under the skin. The device sends the information wirelessly to a smartphone, so users can see if their levels are going up or down. It can also send alerts when ketone levels get too high, which helps people take action sooner and avoid emergencies. The FDA approved the device after looking at data from six studies with over 600 people, which showed the device works well for checking both ketones and glucose over 10 days. This device fits into the FDA’s goal to make health care more accessible at home. The Libre Duo 10 Day got special attention from the FDA because it is the first of its kind, and it went through a special review process for new, low-risk devices.

In the Hacker News comments, many people said this device is a big step for diabetes care. Some users with diabetes or family members with diabetes shared that checking ketones is hard and can be scary, so having both tests in one device is helpful. Others talked about how real-time alerts could save lives, especially for children. Some users wondered about the cost and if insurance will cover it. A few people asked how accurate the ketone readings are compared to standard tests, and if the device will work for people without diabetes who follow special diets. There was also discussion about privacy and data security, as the device connects to a smartphone. Some commenters pointed out the importance of FDA approval, saying it will help doctors trust and recommend the device. Others were excited about how this might push more innovation in wearables for other health issues. Overall, most people agreed that this device could make life much safer and easier for people with diabetes.

It uses a new “quad-die” design, joining four chips together with special technology called UltraFusion. This gives it up to 36 CPU cores, 80 GPU cores, and a huge 512GB of unified memory, with extremely fast bandwidth (1.2TB/s). The M5 Ultra also has a 32-core Neural Engine and special hardware for video editing and AI. Apple says this chip can run really large AI models and handle massive data sets right on the device.

Both chips are designed to help developers run and train AI models locally, using Apple’s tools like Core ML and Xcode. Apple claims the chips are very power efficient, so they don’t get too hot and can save energy.

## OpenAI Jalapeño: Better than Nvidia Blackwell

- 原文链接: [OpenAI Jalapeño: Better than Nvidia Blackwell](https://newsletter.semianalysis.com/p/openai-jalapeno-better-than-nvidia)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49434378)

OpenAI has built a new AI chip called Jalapeño, made for running large language models (LLMs). The article explains how Jalapeño was built fast, works very well, and even beats top chips from Nvidia and AMD in many tests.

Jalapeño is not just for OpenAI models—it is a general chip for AI inference. OpenAI worked with Broadcom to start designing it in mid-2024, and in only 16 months they went from starting to making working hardware. This is much faster than most chip projects. Usually, first-generation chips are not as good as older ones, but Jalapeño is different. It is as fast or faster than Nvidia or AMD chips in most tasks, thanks to careful hardware and software design together.

Jalapeño uses HBM4 memory, which is very fast and new. It can run many open-source AI models and even ran the video game Doom as a fun test. In real benchmarks, Jalapeño gets more tokens per megawatt (a measure of output per power) than any other chip tested, even though it does not use all the special tricks other chips use yet. For example, it does not yet use “speculative decoding,” which saves a lot of cost per token.

OpenAI focused on performance per watt (perf/W) because their main limit is power in data centers, not money or space. This is now true for many companies. Jalapeño is also compared to Nvidia’s new Rubin chip, which is closer to Jalapeño in design than the older Blackwell chip. Even against Rubin, Jalapeño gives better results in some tests.

The chip is built to be flexible, not split into different parts for different tasks. This helps keep all hardware busy, even when the work changes. Jalapeño also has very high memory bandwidth, more than other chips, and the design lets each part of the chip talk to its own memory quickly.

The programming model is new, too. OpenAI uses their own language called Gluon to write code for the chip. They used AI tools like Codex to help write and tune the code, making it easier and faster to get good performance.

Jalapeño’s system can connect many chips together—up to 2,048 in a big network. Power use is high, but this is normal for modern AI data centers.

In the top Hacker News comments, people are impressed with how fast OpenAI built and got Jalapeño running. Some say it shows the power of hardware and software teams working closely together. Others point out that OpenAI had a lot of money and talent to make this happen, and not many companies could do the same.

Many commenters discuss how beating Nvidia is a big deal, since Nvidia’s CUDA software is seen as a strong “moat.” Some think OpenAI’s use of new programming tools could make it easier for others to make custom chips in the future. There is also discussion about power limits in data centers, with several saying that performance per watt is now more important than raw speed.

A few are more cautious, noting that all the numbers in the article come from OpenAI and are not fully independent. Some want to see more tests on bigger models and harder workloads before saying Jalapeño is truly better. Others point out that scaling up production and getting chips into real data centers is still a big challenge.

Some users worry about lock-in if everyone starts using their own custom chips and software, while others are excited by the idea of breaking Nvidia’s dominance. Finally, a few commenters wonder if this signals a bigger change in AI hardware, where fast, custom solutions will become the norm, not the exception.

## Black hole singularity is a surface not a point

- 原文链接: [Black hole singularity is a surface not a point](https://arxiv.org/abs/2608.21590)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49437210)

This article says that the singularity inside a black hole is not a single point, but rather a surface. In popular science, people often say everything inside a black hole collapses to a point at the center, but the paper explains this is not true in general relativity. 

If two people fall into a black hole from different directions, they do not meet at the same spot inside. They actually lose the ability to talk to each other before reaching the singularity, even if they are close in space. This is because, in general relativity, “closeness” in space does not always mean you can send signals or meet. The singularity, where physics breaks down, is a kind of surface inside the black hole, not just a point.

For spinning (rotating) black holes, things are a bit more complex, but the result is similar: the “singular” part is a surface, probably near what is called the “inner horizon.” Small changes or disturbances inside the black hole make this surface very unstable and cause it to collapse. The paper also talks about what this means for quantum gravity. It suggests that the “information” of a black hole is stored on this 2D surface, which interacts with the trapped Hawking radiation inside the black hole.

People in the comments had many thoughts about this idea. Some were surprised, saying they always thought the singularity was a point, and this changes how they picture black holes. Others pointed out that general relativity is strange, and our usual way of thinking about space doesn’t work inside black holes. A few commenters brought up textbooks and older papers, saying this surface idea has been discussed before, but is not well known. Some people liked the connection to the idea that black holes store information on surfaces (“holographic principle”). Others were confused about how two people can be very close but unable to meet, and asked for more simple explanations. There were also technical discussions about the math behind singularities and event horizons. A few doubted if any of this could be tested, since we can’t see inside black holes. Overall, the discussion showed that black holes are still very mysterious, and even basic facts about them can be surprising.

This post explains how to run OpenBSD on DigitalOcean for about $4 a month, instead of using big hosting platforms like GitHub Pages or Cloudflare Pages. The author wanted to get back to the old days of setting up servers and learning by doing things yourself.

First, you download the OpenBSD “miniroot” image from the official site and check its hash to make sure the file is safe. Then, you upload this image as a custom image in your DigitalOcean account—be careful, because storage of custom images costs extra, so delete the image after use. Next, you create a new server, called a “droplet,” using this image. You select the smallest, cheapest plan, which includes 512MB of RAM and 10GB of disk. You also need to add an SSH key, even though DigitalOcean won’t use it yet.

When the droplet is created, you use the web console to install OpenBSD. Most install questions can just use default answers, but you set up the network, create a user, set passwords, and decide if you want full disk encryption. If you pick encryption, you must enter a password after every reboot using the web console. The guide suggests removing some system parts you don’t need, like X11, games, and the compiler. After install, you reboot, SSH into your new server, and finish setup by reading the OpenBSD handbook and improving security, for example by turning off password authentication.

## Bomb fishing is wreaking havoc on Indonesia's coral reefs

- 原文链接: [Bomb fishing is wreaking havoc on Indonesia's coral reefs](https://e360.yale.edu/digest/bomb-fishing-coral-reefs)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49434820)

Bomb fishing is causing big damage to Indonesia’s coral reefs, especially in the Spermonde Archipelago. The article explains how fishers use homemade bombs to catch fish, but these bombs destroy everything around, turning beautiful reefs into fields of rubble.

Researchers found that more than 8,000 bombs go off underwater each year in this area. Each bomb kills fish and coral in a large circle, and the damage adds up quickly. Since 1990, about 75% of the coral in the area has disappeared. The explosions make it hard or impossible for new coral to grow back because the ground is always moving and broken. 

To study this, scientists placed audio recorders underwater and used special computer programs to find the sounds of bombs. They even made their software open for everyone to use. The study showed that bomb fishing happens all year, with most blasts in the morning and fewer on Fridays, which is a local prayer day. The practice is not only found in Indonesia; it happens in many countries around the world.

The article points out that bomb fishing is often done by middle-income fishers, not just the very poor, because it costs money to buy the equipment. The main reasons for bomb fishing are weak laws and not enough enforcement. Even though Indonesia has large marine protected areas, it is hard for police and guards to catch people using bombs.

Some researchers think that if bomb fishing stops, the reefs could recover and become healthy again. The new technology for listening and finding bomb blasts could help fight this problem in many countries, not just Indonesia.

In the comment section, people have a mix of feelings. Some are shocked that bomb fishing still happens, saying it seems like a problem from the past. Others point out that weak law enforcement and corruption make it hard to stop illegal fishing. A few commenters note that poverty and the need for quick money push fishers to use bombs, even if it hurts the long-term health of the ocean. Some suggest that better education and giving fishers other jobs could help. Others are hopeful that new technology, like the audio sensors, can help catch fishers in the act, but some worry about how hard it is to patrol such a big area. There are also voices saying that real solutions need to come from local communities, not just from outside experts. Finally, some people mention that the problem is worldwide, and stopping bomb fishing in one place is only part of the answer.

## When str.lower() is a security vulnerability in Python – Seth Larson

- 原文链接: [When str.lower() is a security vulnerability in Python – Seth Larson](https://sethmlarson.dev/when-str-lower-is-a-security-vulnerability)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49440410)

This article talks about a security issue in Python when using `str.lower()` with domain names. The problem comes from how Python changes letters to lowercase, which is important for following internet rules about domain names.

The article explains that internet standards for domain names need to support many languages, not just English. To do this, they use Unicode, but domain names still need to use only ASCII letters. There are special rules, called StringPrep and IDNA, that help with this. Python supports two versions: IDNA 2003 (old) and IDNA 2008 (newer). The older version, IDNA 2003, uses StringPrep, which depends on Unicode 3.2.0.

StringPrep has a step called “case folding,” which means changing all letters to one case, usually lowercase, so computers can compare them easily. The rules for this are in tables (B.2 and B.3) from the official documents. Python’s code uses `str.lower()` to do this, but the problem is that `str.lower()` uses the Unicode rules from the version of Python you are running, which might be newer than Unicode 3.2.0.

This can create a security problem because the way letters are changed to lowercase can be different in new Unicode versions. For example, if you use Python with Unicode 17.0.0, the result of lowercasing some special characters will not match what is expected from the old rules. This difference can change how domain names are handled, which could let attackers trick systems.

To fix this, the Python team had to create special exceptions so that, for domain names, the code uses the old Unicode 3.2.0 rules only. They checked every letter to see if the lowercase result is different and made sure to handle these cases the right way. Now, Python’s handling of domain names with IDNA 2003 matches the official rules, which is safer.

In the comments, many users point out how tricky Unicode and domain names are, and how small differences can cause big security problems. Some people note that internet standards change slowly, and old rules can stick around for years. Others say that using the newest packages (like the `idna` package for IDNA 2008) is safer, but sometimes you need to support older software.

A few commenters are surprised that such a simple function like `str.lower()` could cause a real security issue. Some share examples from their own work where small changes in Unicode handling broke things. Others worry about how hard it is for programmers to know about these problems, since the standard library looks safe but can have hidden issues.

Some users wonder if other programming languages have the same problem, and a few mention that always using the exact Unicode version needed by the standard is the best way. There’s also talk about how important it is to test your code with strange or unexpected characters, not just basic English. Overall, people agree that Unicode is powerful, but you have to be very careful when using it for security or internet standards.
