Switching to databases, a new article shows that Postgres’s LISTEN/NOTIFY feature can actually scale well, even if many believe it cannot. LISTEN/NOTIFY lets readers know when new data is written, helpful for real-time systems. The usual way is to send a notification every time data is written, but this slows down under heavy load because of a global lock in Postgres. The lock is needed to keep notifications in order, but it blocks fast writes.

To solve this, the team buffered notifications in memory and sent them out in groups. This way, the global lock is only needed once for the whole group, not every time data arrives. If something crashes before the buffer is sent, readers can still poll the table. With this system, they reached 60,000 writes per second, about 20 times faster than before, and kept the delay low.

Comments are mixed. Some users agree with the results and use LISTEN/NOTIFY in production, but with care. Others worry about lost notifications if the process crashes, though polling helps. Some say buffering is good for small or single-node systems, but not for large, distributed ones. Postgres 19 will not fix the global lock, so this method is still needed. A few suggest using external message queues for very high workloads. Many like the simple solution, but warn that every system has limits, so you should test for your own needs.

Now, a story about a big security problem in Hanwha Vision security cameras. Someone found that the cameras’ software had a token giving admin access to Hanwha’s GitHub accounts. The writer downloaded firmware, took it apart, and used tools to unlock files. Inside, they found a GitHub admin token in about 30 files, due to a bad build step that copied secret tokens into the camera’s UI files. Some files even had U.S. Department of Defense IP addresses.

The writer checked about 500 more camera models. In 62% of them, they could extract files, but only three had the same GitHub token. The author reported the problem, and Hanwha quickly fixed it by revoking the token.

Hacker News users were shocked that a security camera had such a basic security problem. Some said this shows companies still do not handle secrets carefully. Others pointed out that adding all environment variables to build files is a common but risky mistake. Some joked about the irony of cameras made for security actually causing security problems. Many praised the author for responsible disclosure and Hanwha for quick action. There were also warnings that this is a common problem in hardware and that companies must do better, especially for products used in homes and offices.

Next, India’s first private rocket, Vikram-1 from Skyroot Aerospace, reached orbit on its first try, making history for India’s space industry. The rocket is smaller than India’s main ones but can carry about 350 kilograms to low-Earth orbit. It uses three solid-fueled stages and a fourth, liquid-fueled stage with a 3D-printed engine. The launch had a short delay and some suspense during stage separation, but everything worked and the rocket reached the planned orbit. It carried two CubeSats and extra payloads.

Skyroot got help from India’s space agency ISRO, which provided testing and launch facilities. The company is now valued at $1.1 billion and plans to build bigger, reusable rockets in the future. The Indian government is pushing for more launches and supports private companies like Skyroot.

Many readers congratulated Skyroot and India. Some compared this to early days of SpaceX and Rocket Lab, noting how rare it is for a new company to reach orbit on the first try. Some discussed the rocket’s design and the role of public-private partnerships. There was debate about how “private” the technology is, since ISRO helped a lot, but most agreed Skyroot’s achievement is impressive. Others were excited about the future of space startups in India and curious about launch costs and global competition.

Now, a talk about Fil-C, a new way to make C and C++ memory safe, shown by Filip Pizlo at SSW 2026. Normal C and C++ are not safe with memory, which can lead to bugs and attacks, so many people want to move to Rust. Fil-C is a new compiler and runtime for C and C++ that adds protections so memory bugs cannot be used to take over programs. Filip showed live demos: running LibreOffice and even a whole Linux distro compiled with Fil-C. The compiler adds memory safety checks at runtime, and all memory is zero-initialized. There’s a garbage collector, so you do not need to free memory by hand.

People in the comments were impressed by the live demos. Some joked that Fil-C is like a fast version of Valgrind, but always on. Others asked about performance and if the overhead is too high for real use. Some think Fil-C is best for testing and hardening, but maybe not for release builds. There were questions about porting Fil-C to other platforms, and some wanted a version for Rust. A few worried about every allocation being zeroed, which could be slow. Overall, people are excited to see safer C and C++ without needing to switch languages, but some still worry about speed.

On to developer tools: marimo, a reactive notebook tool, now works inside PyCharm, a popular Python IDE. The marimo team released a plugin so you can use marimo notebooks right in PyCharm. These notebooks are just normal `.py` files, which is good for version control. When you update code, marimo updates cells automatically, and you can switch between the notebook and code editor. The plugin manages marimo’s server, runs notebooks in your project’s Python environment, and can install marimo if needed. There is also a sandbox mode to keep dependencies separate.

You can use PyCharm’s tools, like database browsing, next to your notebook. The plugin supports pairing with AI agents, so you can get help from AI inside PyCharm. It’s open source and still new, with the team asking for feedback.

Users on Hacker News are excited about better notebook support in PyCharm and like that marimo notebooks are just Python files. Some compare marimo to Jupyter, asking about real-time updates and git support. There are questions about performance, sandboxing, and support for other JetBrains IDEs. Most people are hopeful and interested in trying the new plugin.

Finally, we have a story about building an open source Ethernet switch ASIC, which is a custom chip for connecting network devices. The author is making a 3-port, unmanaged, 100 Mbps switch on a small, affordable chip, hoping to get real chips from the factory later this year. Most open source hardware projects focus on CPUs, but not on networking chips, which are usually closed and complex. The design is for an unmanaged, cut-through switch due to small chip size and pin limits. The chip uses a simple MAC address table with only 4 entries and works with common Ethernet PHY chips.

The author tested the design on an FPGA, but ran into slow network speed due to hardware limits. There are plans for bigger chips in the future, with more ports and better memory.

Hacker News users are excited to see open source hardware moving into networking. Some talk about the difficulty of making and testing ASICs and praise the author’s write-up. There are technical questions about speed, memory, and real-world use. Some share their own FPGA or ASIC stories, and a few suggest this chip is great for teaching or as a starting point for open source routers. There are also questions about toolchains and chip manufacturing, with some explaining how shuttle runs help keep costs low. Overall, people are supportive and encourage more work on open networking hardware.
