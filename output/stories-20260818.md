## Claude Code Teaching macOS to Natively Print to the HP Laser 1008a

- 原文链接: [Claude Code Teaching macOS to Natively Print to the HP Laser 1008a](https://cdn.kuber.studio/chat/hp-laser-1008a-driver)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49352806)

This story is about making an HP Laser 1008a printer work with a new Mac (macOS 26.6). The printer was plugged in by USB, but macOS did not have a native driver for it.

First, the system saw the printer as “HP Laser 1003-1008,” but only offered a generic driver. The author checked if the printer could use AirPrint or driverless printing, but it couldn’t. They tried the generic PCL driver, but when they sent a print job, the printer stayed “offline.” Digging deeper, they found many people online had the same issue: this printer is Samsung-based and needs a special “SPL” or “QPDL” driver.

They tried open-source drivers like “splix-macos” and built it from source, installing special filters and PPDs. Even after building and installing, print jobs still got stuck, and the printer stayed offline. The author found that the USB backend on macOS was not talking to the printer in the way it expected. The printer itself showed as “busy” or “offline” in the logs.

They tried power-cycling the printer and using different open-source tools (like foo2qpdl), but still had problems: sometimes the printer would print garbled pages, sometimes it would do nothing, and sometimes it printed error messages like “SPL ERROR - Please use the proper driver.” The author also tried to send Apple Raster (PWG/URF) files, but this did not work either. They did a lot of detective work, reading device logs, USB profiles, and printer responses.

After many tries, they realized macOS’s CUPS backend doesn’t work well with this printer over USB. The only way to make it print was to write raw data directly to the USB device, bypassing the system’s print backend. Even then, print quality was poor or the printer gave error messages, showing that the SPL dialect or resolution was not matching what the printer wanted.

In the Hacker News comments, some people praised the detective work and deep debugging. Others said this is why they avoid buying printers that don’t have official Mac support. Some suggested using a Raspberry Pi or old PC as a print server running Linux, because Linux drivers (like foo2qpdl or splix) often work better with these printers. A few users shared similar stories about struggling with host-based printers and said AirPrint support is a must these days.

Other commenters pointed out that reverse-engineering printer drivers is very hard, because vendors rarely release specs. Some said HP (and other brands) often rebadge Samsung printers, leading to more confusion. A few people recommended just replacing the printer with a model that supports AirPrint or IPP Everywhere, to avoid all this trouble in the future.

Many thanked the author for sharing all the details, saying it helps others know what to expect before buying certain printers. Some admired the amount of learning and problem-solving, but agreed that for most people, buying a better-supported printer is easier than going this deep into driver hacking.

## Turbovec – Google's TurboQuant for vector search in Rust

- 原文链接: [Turbovec – Google's TurboQuant for vector search in Rust](https://github.com/RyanCodrai/turbovec)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49349898)

Turbovec is a new tool for fast and efficient vector search, built in Rust with Python support, using Google’s TurboQuant algorithm. It helps you store and search through millions of high-dimensional vectors, like those used in AI, but with much less memory—10 million vectors fit in just 4 GB of RAM, much less than usual.

With turbovec, you don’t need to train or tune anything before adding data. You can add vectors at any time, and they are ready to search right away. The search itself uses special processor instructions for speed, working faster than FAISS, which is the current standard for vector search. Turbovec can save your data incrementally, so you don’t lose work, and it makes it easy to filter search results. All data stays on your own machine for privacy.

You use turbovec by creating an index, adding your float32 vectors, and searching for the nearest ones. There are extra tools for stable IDs, so you can add or remove vectors by their own number, and search within a filtered set. Turbovec works with popular frameworks like LangChain, LlamaIndex, and Haystack, making it easy to swap in.

The heart of TurboQuant is how it compresses vectors: it first normalizes them, then applies a random rotation, and then quantizes each number in the vector into just a few bits. This makes the data much smaller but still good for searching. There’s an optional calibration step to make searches even more accurate. For searching, the system rotates the query and matches it directly to compressed data, using fast code paths for modern CPUs.

Benchmarks show turbovec is faster and uses less memory than FAISS for adding, removing, and searching vectors, both on ARM and x86 CPUs. Save and load times are also fast, and the tool is simple to build and use.

In the comments, some people are excited about the speed and memory savings, calling it a strong step forward for open-source vector search. Others ask about real-world recall (accuracy) compared to FAISS, and about how easy it is to integrate with their existing AI tools. Some are interested in the Rust implementation, saying it could help with performance in their own systems. A few users raise questions about hardware support, especially for older CPUs or those without special instructions. There are concerns about how well the tool works with different vector types and bit widths, as well as curiosity about the calibration step and if skipping it hurts results. A couple of people mention they would like to see more benchmarks on varied datasets. Others point out the value of keeping data private and not relying on cloud services. Overall, the community sees turbovec as a promising, fast, and private alternative for vector search.

## The Amazon tax

- 原文链接: [The Amazon tax](https://seths.blog/2026/08/the-amazon-tax/)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49345263)

This article talks about how Amazon makes huge profits from search ads on its website, which the author calls an “Amazon tax.” Amazon earns about a billion dollars each week by showing ads to people searching for products, and this hurts both sellers and buyers.

The article explains that sellers, like book publishers, buy ads on Amazon to help customers find their products—even when people are already searching for those exact items. For example, the author’s publisher paid Amazon a dollar for every person who clicked on an ad for a book they already wanted to buy. The ads do not help customers find better products; instead, they often push people toward different or worse options, just because those companies paid for ads.

Because of this system, even the makers of the best products must buy ads to protect their sales. If they don’t, their products could be buried under ads for other, maybe worse, products. This makes advertising a must, not a choice. The article says that, unlike old-fashioned ads that make people want new things, these search ads just shuffle sales between sellers—they don’t increase total sales. In fact, a study shows that adding ads might even make a website sell fewer items.

The cost of these ads—over $50 billion each year—ends up in the price of products. This means customers pay more, or companies have less money to make better products. The system also encourages sellers to spend more on ads and less on making good products. Plus, Amazon has a reason to make its regular search results worse, so that more people feel forced to buy ads.

The author points out that Amazon used to be good for customers and sellers, offering low prices and fair access. But now, the ad system mainly helps Amazon, not shoppers.

In the Hacker News comments, some people agree, saying Amazon’s search is now full of ads and feels worse than before. They miss when finding good products was easy, and think Amazon’s focus has shifted from helping customers to making money from ads. Other commenters say that Amazon is just doing what other big tech companies do, like Google, and that paid ads are common in online business. A few people think sellers are still free to not buy ads, but most agree that it’s hard to stay visible without them. Some worry that this trend will lead to lower-quality products, because money goes to ads, not improvements. Others say the cost of ads will be passed to buyers, so everyone ends up losing. A few hope for new shops or websites that can challenge Amazon by being better for both customers and sellers. Some users suggest using browser plugins or other tools to block ads, but know it is not a full solution. Overall, the comments show that many people are unhappy with how Amazon’s ad system affects shopping online today.

This article talks about the “Dilbert Principle,” which says that some companies promote bad workers to management to keep them away from important tasks. The idea is that if someone is not good at their job, moving them into a manager role can limit the harm they do to the real work of the company. The article points out this is a cynical way to manage people, since it suggests that regular workers do the important jobs while managers sometimes just get in the way.

The article explains that being a good engineer and being a good manager are very different skills. Just because someone is not great at engineering does not mean they will be good at leading people. When companies promote weak workers instead of dealing with their problems, they end up with managers who don’t have respect from the team or the right skills to lead. This can lead to bad choices, missed goals, and a lack of trust between workers and bosses.

The article shares stories from tech workers who have seen this happen—where a failing programmer or team lead is “promoted” to manager or architect, not as a reward, but to get them away from hands-on work. This often makes things worse, because now the team has a bad manager and one less developer. However, the article also says that some companies are getting better. They now offer two tracks: one for people who want to stay technical, and one for those who want to manage. Good companies will coach or move struggling workers, and only make them managers if they are actually suited for it.

The “Dilbert Principle” comes from a book by Scott Adams in 1996. The book uses jokes and cartoons to talk about the silly things that happen in offices, but many workers say the stories feel true.

People in the comment section share different views. Some say they have seen this in real life, where weak workers are moved into management just to get them out of the way. Others point out that this can create a chain of bad managers, making the whole company weaker. A few think this problem is less common now, because tech companies are learning and creating better career paths for engineers. Some commenters share stories of good managers who were promoted for the right reasons, and say that management can be a skill worth learning. Others feel frustrated, saying that when management is seen as a “safe spot” for poor workers, it hurts the whole team. Some people argue that it’s better to help struggling workers improve or let them go, rather than give them more power. Others joke that sometimes it’s just easier to move the problem rather than have a hard conversation. A few say that in some companies, being a manager is actually much harder and not a reward at all. Some commenters mention the “Peter Principle,” which is a similar idea: people get promoted until they reach a job they can’t do well. Overall, most agree that giving the right people the right jobs is important for everyone.

## Using the railway network as a flatbed scanner

- 原文链接: [Using the railway network as a flatbed scanner](https://philo.gay/linecam/)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49344825)

This article is about using a special camera to make huge, detailed pictures by pointing it out the window of a moving train or ferry. The author built a system that works like a flatbed scanner, but uses the motion of trains to “scan” the view outside.

The main idea is to use a line scan camera, which only captures one line of pixels at a time. As the train moves, the camera stitches these lines together to form a very wide image. The author first tried this technique at home by pushing a phone along a sofa and grabbing lines from the video, but the results were messy because the speed was not steady. To fix this, they tried to measure how fast the camera was moving by using phone sensors, but the data was too noisy.

Later, they bought an industrial line scan camera, which can capture thousands of lines per second. This camera needs a lot of light, so it only works well during the day. The author also made a 3D-printed case to hold the camera and added more sensors: an accelerometer (to measure movement), a GPS (which often failed on trains), and a microcontroller to manage data. They had to write special software to process the camera and sensor data, which took a lot of work and troubleshooting.

When processing the images, the biggest challenge was to match up the camera lines with the correct train speed, because even small speed changes can stretch or squish the image. They also had to deal with parallax (things close to the train move faster in the image than far-away things) and very large file sizes. Color images added more problems, like colors looking strange because the camera sees infrared light, and colored fringes because the sensor’s red, green, and blue lines are separated.

The author shared that showing these giant images on a computer is hard, but they used special tools to make zoomable web galleries. They hope to improve the hardware and software in the future, maybe making everything smaller and adding new features like better GPS and new photo effects.

In the comments, readers found the project very creative and fun. Many were impressed by the technical work and the beautiful, strange images it produced. Some commenters compared this to other “slit-scan” photography and shared their own experiments—one person tried a similar method with a GoPro and bike, but had trouble with speed changes too. Others pointed out that this method is like how some industrial machines inspect materials, so it’s cool to see it used for art. 

A few readers noted the problems with GPS in tunnels and suggested using train schedules or wheel sensors for better speed data. Some wondered about privacy and how people react to seeing the device on public transport. Others gave tips for working with huge image files or suggested trying this on other vehicles, like buses or even planes.

There were also practical questions: How does the author deal with train window reflections? Is it hard to get good light? A few people asked for more details about the code and hardware, and were glad to see the author linked their GitHub. Some readers said the results reminded them of old panoramic paintings, and liked how this mixed art and engineering. Overall, people enjoyed seeing a technical project turn into something visually interesting and unique.

## Fixing a bricked Framework laptop

- 原文链接: [Fixing a bricked Framework laptop](https://quantum5.ca/2026/08/16/fixing-bricked-amd-7040-series-framework-13-laptop-with-20-tools/)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49345220)

This article tells the story of someone who bought a Framework 13” laptop because it was easy to repair and worked well with Linux. After three good years, they tried to install a new BIOS update (version 3.20), as Framework suggested for better security, but the update failed and broke the laptop.

The laptop would not turn on, showing only a strange screen. The writer contacted Framework support, but because the warranty had ended, Framework only suggested buying a new motherboard for over $500. They did not offer real help for fixing the laptop, not even a BIOS image or instructions. The author found many other people had the same problem with this update and older BIOS versions. Framework had not admitted there was a problem.

Instead of buying a new motherboard, the writer decided to fix the laptop by themselves. They learned that the only way was to flash the BIOS chip directly. This chip is hard to reach and not in a socket, so it needs special tools. The author bought a “pogo pin” probe, a cheap USB flash programmer (the CH347), and a level shifter to use the right voltage. They read about how to use these tools and carefully checked the connections to avoid damage.

To get the right BIOS file, they had to extract it from Framework’s update file using a special tool, since Framework did not provide it directly. After the tools arrived, the writer connected everything, held the probe on the chip, and used the “flashrom” program to write the BIOS. It took less than a minute. After this, the laptop worked again, but some settings and serial numbers were lost, and they had to fix the Linux bootloader.

The writer was upset with Framework for many reasons: the broken BIOS update, no real support, making repair harder by not using a socket for the BIOS chip, and not giving users the files or guides needed. They felt Framework did not really support the “right to repair.” The article ends with a list of ways Framework should improve, such as fixing the updater, helping customers with repairs, and being more careful with customer data (there was also a data breach).

In the Hacker News comments, many people agreed that Framework’s response was poor and did not match their promise of repairability. Some said the lack of a recovery feature for the BIOS was a big mistake, especially since older and even less “repairable” laptops often have this. Others shared stories of fixing their own devices with similar tools and felt the process was not too hard, but still too difficult for non-technical users. Some users pointed out that using a non-socketed, hard-to-access chip saves space and money but hurts real-world repair.

A few commenters said that bricking during BIOS updates is always risky, and users should wait before applying new updates. Some were disappointed that Framework did not provide better support, especially since many others had the same problem. Others thought the article was a good guide for anyone trying to fix a BIOS, and that learning these skills is valuable.

Some people defended Framework, saying that it is still better than most companies for repair, but most agreed that in this case, Framework let users down. There were also comments about the risk of data breaches and the need for companies to protect customer data better. A few commenters noted that the tools are cheap but not user-friendly, and that most laptop owners would not be able to do this repair themselves. Many hoped Framework would listen to stories like this and improve their support and design in the future.

## How does IKEA come up with names for its products?

- 原文链接: [How does IKEA come up with names for its products?](https://www.ikea.com/se/en/customer-service/knowledge/articles/6f564c4d-2ccc-46de-b643-545a3948dc79.html)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49349984)

IKEA gives its products Swedish names instead of numbers because the founder, Ingvar Kamprad, had trouble remembering numbers. This naming system started as a practical idea but has now become a big part of IKEA’s brand and style.

IKEA uses Swedish words for almost all its product names. These names often come from Swedish places, common names, nature, or simple Swedish words. For example, sofas are named after Swedish towns, bookshelves get men’s names, and children’s products use names of animals or things from nature. To become a product name, the word must be real, have 4 to 12 letters, sound pleasant, and sometimes include Swedish letters like Å, Ä, or Ö. IKEA makes sure the names are not already trademarks, not surnames, and do not have bad or strange meanings in other languages. They check each new name carefully, with the goal to avoid problems in any country.

For things that are not products, like services or features, IKEA uses simple, descriptive words in the local language of each country. But, some friendly Swedish words (like “hello” or “coffee”) are used everywhere to share a bit of Swedish culture. IKEA creates 2,000–3,000 new product names every year.

In the comments, some people say they enjoy the fun and playful feeling of IKEA names, even if they do not understand them. Others share stories about mispronouncing the names or thinking they are made-up words. A few Swedish speakers find it funny when the names are everyday words for them, like “sofa” or “bookshelf.” Some users think the system is clever and helps IKEA stand out among other stores. Others wonder if the company has trouble finding enough new names each year. There are comments about IKEA sometimes missing strange meanings in other languages, causing a joke or confusion. A few people like that IKEA checks for bad meanings, while some say it would be hard to check every language. Some users wish more brands would use real or fun names for products, instead of numbers. One person says the naming system helps them remember products better, but another prefers clear, simple names. Overall, the comments show most people find IKEA’s naming style interesting and unique, even if it’s sometimes confusing.

## Cursor launches Origin, GitHub alternative

- 原文链接: [Cursor launches Origin, GitHub alternative](https://cursor.com/changelog/origin-code-hosting)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49334209)

Cursor has launched a new service called Origin, which is a place to host your code, similar to GitHub. The feature is now in early beta and is available for users on paid plans.

With Origin, you can create new code repositories, push your projects, and browse your code right inside Cursor. There is a new "Codebase" tab where you can manage these repos, and you can easily start by clicking "+New" to make a fresh repo. After creating a repo, you get clear instructions on using the command line to clone or push code. Each repo gets a unique URL based on the name you choose.

Origin also lets you connect your GitHub account. This means you can see both your new Origin repos and your existing GitHub repos in one place. You can pick which GitHub repos to sync, and syncing works both ways—any changes, comments, or pull requests update in both Cursor and GitHub almost instantly. Icons show if a repo is hosted on Cursor or comes from GitHub.

For code review, every repo supports pull requests. You can see all the details, like commits and file changes, and leave comments or merge changes. Pull requests on synced repos also sync comments and reviews both ways with GitHub.

Cursor builds in "agents," so you can ask questions about your code, get help, or even have the agent make changes for you, all from the same place. There are also app extensions—integrations with services like Vercel, Depot, and Buildkite, letting you connect these tools for things like preview deployments or running tests.

You can manage settings for each repo, such as who can access it, which apps are connected, and the sync status with GitHub. The feature is rolling out now to most paid users, except some enterprise groups.

In the Hacker News comments, some people are excited to see a new competitor to GitHub, saying more choices are good for everyone. Others question if Cursor can really challenge GitHub, which is very popular and trusted. Some users like the idea of having AI agents work with their code directly inside the same tool. A few people worry about putting their code somewhere new and wonder about security, privacy, and uptime. There are positive comments about the real-time syncing with GitHub, with people saying it could make workflow smoother. Some are interested in the app ecosystem and how easy it will be to connect other tools. Others mention concerns about getting locked into another platform or about what happens if Cursor changes its pricing. A couple of users ask about open source support or self-hosting options, but it looks like Origin is only available for paid plans now. Some developers think the integration of code hosting and AI could be the future, while others prefer to keep things simple and stick with what they know. Overall, the discussion shows both interest and caution from the developer community.
