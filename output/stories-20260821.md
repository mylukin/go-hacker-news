## Kobo can run apps now

- 原文链接: [Kobo can run apps now](https://bandarlabs.github.io/Cobalt/)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49390427)

Kobo e-readers can now run apps using a new open-source platform called Cobalt. With Cobalt, users install a launcher and app store on their Kobo Clara BW device, which lets them download, update, and remove apps over Wi-Fi.

Each app runs as its own process and cannot access device resources directly—apps must ask for network or storage access, which adds a layer of security. The platform uses signed packages to make sure apps are safe to run. If the Kobo is restarted, it goes back to its regular reader mode, so the changes are not permanent.

There are many apps already available. Some examples include an arXiv reader for research papers, Sudoku, Morse code flasher, a Hacker News client, RSS reader, eBook reader for sources like Project Gutenberg, and even a terminal app. There’s also a daily news brief, todo list, tic-tac-toe, and more. The UI is designed for e-ink screens, and the apps are written in Rust using a simple SDK. Developers can create new apps with just a few commands and submit them via pull requests.

Apps are installed and updated by downloading signed binaries from a fixed GitHub release. The system checks signatures before running anything, helping ensure safety. Updates and installs are safe to recover from if interrupted. The setup needs a Kobo Clara BW and a USB connection for the first install; after that, everything works wirelessly. The platform is not made by Kobo itself, and only the Clara BW is fully supported right now.

In the Hacker News comments, many users were excited about bringing more functionality to e-readers. Some praised the open-source approach and the use of Rust for safety and modern development. A few people liked the idea of reading arXiv papers or browsing the web on an e-ink screen, saying it helps avoid distractions. Others pointed out the limited device support—only the Kobo Clara BW works for now—and asked about support for other Kobo models.

Some commenters worried about security or the risk of breaking their device, but others explained that Cobalt doesn’t replace the bootloader and a reboot returns to normal. There was interest in the SDK and how easy it is to start building apps. A few people wanted to see more games or even offline Wikipedia access. Some compared Cobalt to jailbreaking Kindles, noting Kobo devices have always been more open to hacking. Finally, some users warned to be careful and not to try this on unsupported models.

## Scientists release biggest 2D map of the universe

- 原文链接: [Scientists release biggest 2D map of the universe](https://newscenter.lbl.gov/2026/08/10/scientists-release-biggest-2d-map-of-the-universe/)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49392200)

Scientists have made the biggest 2D map of the universe, using data from many telescopes and years of work. This map, called the DESI Legacy Imaging Survey, has over 5.6 trillion pixels and shows about 4 billion stars and galaxies.

The map covers about 75% of the sky in visible and near-infrared light, letting people see far into the universe beyond the dust and stars of our own galaxy. Anyone can look at or use this map, including professional astronomers and citizen scientists. With this map, people can search for special events like supernovae or rare things like gravitational lenses. It also helps scientists study dark matter and dark energy—two very mysterious parts of our universe.

The map was built by combining 263,407 images from three big surveys: DECaLS, MzLS, and BASS, plus data from the WISE satellite. More than 160 scientists helped collect the data, and a smaller team made the final map. The map is important for the Dark Energy Spectroscopic Instrument (DESI), which uses it to pick targets for making a 3D map of the universe. This is key for learning how galaxies gather and how dark energy changes over time.

The project needed a lot of computer power. It took a year to make the code and eight weeks of supercomputer time to process the images. The map will also help new telescopes and AI tools in the future. It is supported by many science groups and countries.

In the Hacker News comments, some people are amazed by the size and detail of the map, calling it a great example of teamwork and technology. Others talk about how useful this data will be for new discoveries and for training AI to find patterns in space. A few mention that open data like this helps both experts and beginners learn about the universe. Some users wonder about the storage and computer power needed for such a huge project. Others share links to the map viewer and encourage everyone to explore the sky themselves. There are also questions about how the map will be updated as new data comes in. Some users remember older sky surveys and are surprised by the progress. Overall, most comments are excited and hopeful about what we can learn from this new map.

## I accidentally logged hundreds of thousands of phone calls to military bases

- 原文链接: [I accidentally logged hundreds of thousands of phone calls to military bases](https://lina.sh/blog/hijacking-e164-arpa)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49387570)

This story is about someone who took control of special internet domains used for routing phone calls, and by accident, logged hundreds of thousands of calls to military bases. The domains are part of an old system called ENUM, which turns phone numbers into special DNS names so calls can be routed over the internet instead of regular phone lines.

The author explains that ENUM uses the e164.arpa domain. When you reverse a phone number and add dots, it becomes a domain like 6.5.4.3.2.1.0.3.9.4.e164.arpa for a German number. Each country had its own part of the system, but most of the world stopped using it years ago. The author noticed that some of these domains for small territories were still delegated but not really managed. By buying an expired domain for just 5 euros, they got control of the phone routing for Saint Helena, Diego Garcia, and Ascension Island—places with important military bases.

This meant the author could see and even control how calls to these locations were routed. At first, they thought nobody used the system anymore, so they hosted websites and other fun things on the domains. But after six months, they checked the logs and found hundreds of thousands of ENUM DNS queries, mostly from American IP addresses, all for the military bases. This showed that real calls to soldiers and their families were still using this old system, making it possible for a bad actor to spy on conversations.

The author reported the problem to authorities, but at first, nobody cared. Only after the author mentioned military bases did the UK’s National Cyber Security Centre take action. In the end, the author handed control of the domain to the NCSC, but the old, broken setup was never fully fixed.

Hacker News readers had a lot to say. Some were amazed that such an old and forgotten system was still in use for sensitive military calls. Others pointed out this is a classic example of “dependency rot,” where systems rely on things everyone has forgotten about. A few commenters were surprised that basic internet hygiene like renewing important domains was ignored for so long.

Several readers worried about how many other parts of critical infrastructure might be open to similar attacks, due to forgotten domains or systems. Some joked about how easy it was to hijack these domains, while others felt the author was lucky not to get in trouble with the law. A few people discussed the risks of logging and handling sensitive data, praising the author for deleting the logs and acting responsibly.

Others noted how hard it is to get big organizations or governments to care about technical risks until something dramatic happens. Some wondered whether attacks like this are already being used by hostile countries. Finally, there was praise for the clear and honest write-up, and for sharing a story that mixes humor with a real warning for anyone working in tech.

## DeepSeek-v4-flash-vision-exp

- 原文链接: [DeepSeek-v4-flash-vision-exp](https://api-docs.deepseek.com/guides/vision/)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49386163)

DeepSeek-v4-flash-vision-exp is a model that lets you send both images and text, so you can ask the model to describe pictures, read screenshots, or look at charts. You can use image formats like JPEG, PNG, GIF, or WebP, and the system checks the real file type, not just the file name.

There are three ways to send images. First, you can use base64 to put the image straight into your request. Second, you can give a link to an image on the internet, but the link can't be too long and the image can't be too big. Third, you can upload a file with the Files API and then just send the file ID when you want to use it, which is good if you use the same image more than once or if the image is large.

For images, you can pick a “detail” level. The “low” option makes the image smaller and is faster and cheaper; “high” or “original” keeps the image size, and “auto” just picks the best option (right now, it’s the same as “original”).

There are size limits: the biggest request body is 48 MiB if you send images directly, or up to 200 MiB if you use file IDs. Each image can be up to 32 MiB directly, or 64 MiB with a file ID. You can send up to 600 images in one request, but the biggest image side is 8192 pixels. If you send a lot of images, the max size per image goes down.

The model only lets you send images in “user” messages, not in “system” or “assistant” messages. Only vision models, like deepseek-v4-flash-vision-exp, accept images.

You can use DeepSeek with the OpenAI API style, or with the Anthropic API style, which has a slightly different way to send images but supports all three methods: base64, URL, or file.

When you send an image, it is turned into tokens, depending on its size. Small images are made a bit bigger, and big images are made smaller so they fit about 800x800 pixels. Each image uses up to 384 tokens, no matter how big it was before resizing.

In the comments, some people liked that the API supports many formats and is OpenAI-compatible, making it easy to use. Others were happy about the clear size limits and the three ways to upload images, as this helps with different use cases. A few users asked about privacy and security when sending images, and wanted to know how DeepSeek handles user data. Some worried about the 48 MiB request limit, saying it could be a problem for big batch jobs, but others pointed out that the Files API solves this for bigger images. There were questions about how fast the model works, especially with many images, and if the “low” detail mode is good enough for basic tasks. A few people wanted to see examples with more programming languages, not just Python and curl. Some users also discussed how this could help in real tasks, like reading receipts or checking screenshots for errors, and wondered about the cost of image tokens. Overall, people saw this as a useful tool, especially for developers who work with images and AI.
