## hdiutil is deprecated in macOS 27 Golden Gate

- 原文链接: [hdiutil is deprecated in macOS 27 Golden Gate](https://lapcatsoftware.com/articles/2026/8/7.html)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49402741)

Apple is removing the old ‘hdiutil’ command-line tool for disk images in macOS 27 Golden Gate and wants everyone to use ‘diskutil image’ instead. The article explains what’s changing, which features may be lost, and how the new tool compares to the old one.

The ‘hdiutil’ tool helped people create, resize, and manage disk images, but now it’s marked as deprecated. Apple says to use ‘diskutil image’ for all these jobs. Most commands from ‘hdiutil’ are still there but with new names, and some are missing. For example, the ‘-puppetstrings’ option, which gave easy-to-read progress for other programs, is gone. Several special options for making images from folders, like ‘-[no]crossdev’, ‘-[no]scrub’, and ‘-skipunreadable’, are also missing.

The writer tested both tools by making a backup of a home folder. Using ‘hdiutil’ took about 110 seconds and needed admin rights because some files belonged to the root user. It showed a clear error about needing authentication, and after giving the password, it finished the backup.

Using the new ‘diskutil image’ command, the process failed at first with a simple error: “Operation not permitted.” It didn’t ask for a password or explain the problem. After deleting the root-owned file, it worked and finished much faster—about 40 seconds. The disk image was also smaller, 2.8 GB compared to 2.89 GB with ‘hdiutil’. One difference was that ‘diskutil’ did not include the Trash folder, behaving as if the ‘scrub’ option was always on.

The writer thinks ‘diskutil’ needs better error messages, better handling of file permissions, and an option to control scrubbing. He also doesn’t understand why Apple is removing ‘hdiutil’ if the same features can be in ‘diskutil’. This change could break old apps and scripts that use ‘hdiutil’. He is also frustrated that a known bug about certain files is still not fixed and Apple support was not helpful.

In the comments, many people are annoyed by Apple removing old tools, saying it breaks their scripts and workflow. Some agree that ‘diskutil’ is faster, but they worry about missing features and less control. A few users are concerned about tools and automation that depend on ‘hdiutil’, especially for backup jobs and app development. Others point out that Apple often changes or removes command-line tools without good explanations. Some think the change could be good if ‘diskutil’ improves, but they want better documentation and clear migration guides. A few comment that the new tool’s error messages are not helpful, making debugging harder. There’s also talk about Apple’s slow bug fixes and confusing support responses. Some people hope third-party tools will fill the gaps, while others plan to delay upgrading or keep old systems for as long as possible.

## Why your local LLM feels dumber than it is

- 原文链接: [Why your local LLM feels dumber than it is](https://forum.level1techs.com/t/why-your-local-llm-feels-dumber-than-it-is/253917)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49402232)

This article talks about why a local large language model (LLM) on your computer can feel less smart than you expect. The author explains that even if you download a well-known LLM, it often performs worse than you saw in demos or heard about online.

The main reason is that every person runs LLMs on different hardware and software. GPUs (graphics cards) and their drivers are different. The math used to calculate the next word can change based on these differences. Even small changes can make the model give different results. The best way to test your setup is to use real benchmarks that match what you want to do—just using a few test prompts is not enough.

The article explains how LLMs decide what word comes next. The model uses numbers called logits, then changes them into probabilities. Settings like temperature and top-p affect the results. If you use the wrong settings, the model might get stuck or repeat itself.

There are many ways your LLM can go off track. The software stack is huge, with hundreds of small pieces, each with possible bugs. Even just changing the attention backend (the part that handles how the model pays attention to input) can cause different outputs. The article shows tests where different backends, or using different number formats (like BF16, FP8, INT8, or INT4), cause the model to pick different words after a while—sometimes making big mistakes.

One main problem happens with long inputs. If you use quantization to save memory (like storing numbers in INT4 or INT8 instead of BF16), the model can start making more errors after 40,000 tokens. Some quantized models fail to finish tasks correctly, like making the wrong command in a test with Cisco devices.

The article also compares different models and quantization methods. Some methods, like INT8 with BF16 activations, work better than others like NVIDIA’s FP4. The more you quantize, the more mistakes the model makes, especially in long tasks.

Many people in the comments agree with the article. They share their own stories of local LLMs acting weird or making errors that don’t show up in demos. Some users say that matching the right settings and hardware is hard, and that even small changes can ruin performance. Others point out that open-source models are often not fully tested on all types of hardware.

Some commenters say that people expect too much from small or quantized models. They think that running big models on weak hardware will always mean worse results. A few users suggest that better documentation and standard tests would help people see what their setup can really do.

There are also comments about how confusing it is to set proper parameters like temperature and top-p. Some users wish there was an easy way to auto-tune these settings. Others say that comparing models is hard because everyone uses different tests and benchmarks.

One person mentions that the field changes quickly, so today’s “best” setup might be old news next month. Another user says that most people just want something that works, even if it's not perfect, and that perfect results are not needed for casual use.

Overall, readers agree that running LLMs locally is tricky, and small details matter a lot. Many hope for better tools and guides in the future.

## Hister – A private, full content search index that you control

- 原文链接: [Hister – A private, full content search index that you control](https://hister.org/)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49351802)

Hister is a tool that lets you build your own search engine for pages and files you pick, and you run it on your own computer or server. It is free software and focuses on privacy, with no tracking or cloud requirements.

With Hister, you can index the full content of web pages, documents, and files, not just their titles or links. You can search through everything you’ve added—even the words inside each file—using simple or advanced search features like field filters, quoted phrases, and wildcards. Hister gives you a preview of the file’s content right next to the search results, so you can see what’s inside without opening the actual document.

You can add content to Hister in different ways. There is a browser extension to save pages as you visit them, you can watch folders on your computer, import your browsing history, or crawl entire websites. All the information and rules stay on the server you control, and the software never sends your data anywhere else unless you choose to, for example, using optional features like semantic search.

Hister supports many ways to search: through a web page, in your terminal, using a command line, or even with an AI assistant. It works with both single users on a personal machine or multiple users on a shared server. You can use SQLite or PostgreSQL for storing the search index, and it’s easy to run with Docker or Nix.

Extra features include version tracking for documents, checking for sensitive content, and support for different languages and file formats. The software is open source, so anyone can look at the code and make sure it’s safe.

People in the comments like that Hister is private, self-hosted, and gives them full control over their data. Some think it’s great for people who want to keep track of everything they read or work on, without relying on big tech companies. Others point out that setting up your own server or handling databases might be too hard for non-technical users. A few say that having previews and searching inside files is very useful, especially for researchers and developers.

Some users compare Hister to other tools like Docspell, Recoll, or desktop search engines, and discuss which one fits different needs best. One comment says privacy is a big advantage, but another wonders if people will want to run their own search engine instead of using Google. Some are excited about the open source license and plan to try it out, while a few worry about long-term support and updates.

Overall, many agree Hister fills a gap for people who want to keep and search their own digital knowledge privately. Still, they note that it may not be for everyone, especially those not comfortable with technical setups.

## A Friendly Introduction to Racket

- 原文链接: [A Friendly Introduction to Racket](https://geometridae.bearblog.dev/a-friendly-introduction-to-racket/)
- HN链接: [Hacker News讨论](https://news.ycombinator.com/item?id=49399898)

This article talks about Racket, a programming language that is part of the Lisp family. The writer wants to help new people learn Racket in a simple way.

Racket is known for its clear and simple rules. It uses lots of parentheses, which can look strange to beginners, but these help show how code is grouped. Racket’s syntax is very regular: most things are written like (function arguments). This makes it easy to read and write once you get used to it. You do not need to remember many special rules or exceptions. Racket also supports functional programming, which means you can write code using functions and avoid changing values. This style can make programs safer and easier to test.

Racket has good support for teaching and learning. There are tools and books made for students. Racket also lets you create your own languages, which is fun for people who like to experiment. The language has strong error messages, so if you make a mistake, Racket tries to help you understand what went wrong. It also comes with a package manager, so you can easily share your code or use code from others. Racket is used for web servers, scripting, and even games.

People in the Hacker News comments have different opinions about Racket. Some think it is a great language for learning and teaching. They say the documentation and community are very friendly. Others mention that Racket is slower than some other languages, so they would not use it for very big or fast programs. A few people say that writing code with lots of parentheses is hard to read at first, but gets easier with practice. Some like that Racket is very flexible—you can change or extend the language itself. Others warn that Racket is not used much in jobs, so learning it may not help your career. Still, some users love how Racket makes them think differently about programming. Many agree that trying Racket can help you become a better coder, even if you do not use it every day.
